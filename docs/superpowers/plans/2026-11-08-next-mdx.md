# Migração Next.js e MDX

**Objetivo:** executar todas as páginas públicas e internas pelo App Router do Next.js, com composição em MDX e componentes React interativos existentes.

**Arquitetura:** cada rota tem seu `page.mdx`. Um limite cliente compartilha sessão, navegação e layout do CRM; permissões continuam no backend e nas configurações. Links antigos com hash são convertidos para rotas nativas. Em desenvolvimento Next encaminha `/api` ao Fastify local; em produção Fastify atende API e delega páginas ao Next no mesmo processo. Credenciais ficam exclusivamente no backend e no arquivo local ignorado pelo Git.

**Tecnologias:** Next.js 16, React 19, @next/mdx, Tailwind CSS 4, Fastify e PostgreSQL.

## Decisões e evidências

- Branch local `refactor/next-mdx`, sem publicação automática.
- Os componentes antigos saíram de `src/pages` para `src/features`: `pages` é uma pasta reservada do Next e estava criando rotas extras.
- O carregamento programático de Next no backend usa `createRequire`, de acordo com a exportação CommonJS da biblioteca; o resto do backend continua ESM/NodeNext.
- O usuário acrescentou a referência AnimatedSidebar durante a migração. Integração com Motion, Radix Dialog e Lucide, usando sessão e rotas reais do CRM; atalho Ctrl/⌘B, submenus, recolhimento e foco no celular.
- Testes web: 50 aprovados. Primeiro build Next: compilação e tipos aprovados, todas as rotas geradas.
- Backend: 64 testes aprovados e 15 testes de integração com banco descartável não executados localmente; teste adicional garante delegação ao Next e proteção de APIs desconhecidas.
- Chrome no build de produção: todas as telas internas e públicas, navegação nativa, hash legado, sessão compartilhada, recolhimento, submenus móveis e restauração de foco aprovados com API simulada.
- A revisão identificou a perda de cabeçalhos no `reply.hijack`. O teste reproduziu a falha; os cabeçalhos foram movidos para `onRequest` e o teste passou.
- Validação final: `npm run validate` aprovado (118 testes aprovados, 15 testes de integração com banco descartável ignorados), incluindo build de produção.
- Chrome no build final também confirmou Ctrl/⌘B, preferência por movimento reduzido e bloqueio da tela administrativa para atendente sem consultar `/api/users`.
- Capturas de Início, Funil, Contatos e Usuários em 390, 768 e 1440 px: sem rolagem horizontal nem campos cortados. O relatório ainda aponta alvos pequenos em controles existentes do funil e contatos no celular/tablet.
- Healthchecks do Next local e do servidor de produção temporário: HTTP 200 e `database: connected`. Retorno OIDC local aceito pelo Auth. Nenhum teste de negócio executado contra produção.
- Revisão final aprovada após correção dos cabeçalhos. Dockerfile atualizado; construção de imagem Docker não executada nesta máquina.
